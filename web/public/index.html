An always-on sales operator that proves its own work.

ProofRun finds local businesses with weak websites, audits them against 13 automated checks, rebuilds the page as real HTML and CSS, then runs the same check code against its own output and repairs what fails. It drafts the outreach email in your voice and stops. You approve everything — nothing is ever sent.

The part that matters

Writing the page is the easy half.

Any model can produce HTML and tell you it is an improvement. ProofRun is built around the other half: loading its own output in a real browser and measuring it with the same code that condemned the original.

An agent that writes a page and tells you it is better is an expensive opinion.

So the audit and the verification share one module. The 13 checks that find the original's defects are the same 13 functions, with the same thresholds, that run against the rebuild. There is no second, friendlier scoring path for the model's own work.

When a check fails, the failing measurement itself is what goes back — the string length, the contrast ratio, the overflow in pixels. A repair prompt that says “title is 78 characters, limit 60” produces a fix. One that says “improve the title” produces another opinion.

It fails open

At the retry cap the run is marked failed, the UI says so plainly, and no draft is written. A rebuild that cannot pass is never pitched.

Every attempt survives

Failed attempts stay in the log with their measurements. The Proof screen shows the whole sequence, not the winning frame.

Numbers come from code

Scores, deltas and pass counts are computed by the check suite. The model narrates them; it never produces them.

The check suite

Thirteen checks, and the limits of each one stated.

Weights decide the score. The limit column is not a disclaimer bolted on afterwards — it ships in the catalogue beside every check, renders in the app, and is the reason a finding can be trusted at all.

Memory

Rejecting a draft changes the next one.

Approvals and rejections are not logged and forgotten. Each decision can carry a rule, the rule lands in a memory file, and every later draft reads those rules before it writes a word.

Plain files, not a black box

Memory is Markdown and JSON on disk — memory/learnings.md, memory/profile.md, your voice sample and offer. The Memory screen renders the same files the agent reads, so you can see exactly what it has concluded about your preferences and delete anything wrong.

The claim is tested, not asserted

“It learns from your feedback” is the easiest unfalsifiable claim in agent software, so there is a script whose only job is to falsify it:

$ node scripts/try-memory.js
→ draft A written with empty memory
→ rejection recorded with a rule
→ draft B written with that rule in memory
✓ drafts differ — exits non-zero if they do not

It diffs the two drafts and fails the process if memory made no difference. The feature cannot silently rot.

Guardrails

The agent runs overnight. It still cannot touch anything.

Autonomy is bounded by what the code physically cannot do, not by instructions asking it to behave.

gate

Nothing is ever sent

There is no send transport in the project. Approved drafts are exported to a file for you to use. agent/send-adapter.js throws if something tries to call it.

sandbox

Generated code is contained

Three layers: a static gate rejecting scripts, external references and inline handlers; network deny-all except the local file under test; and a child process with a scrubbed environment, 512MB heap cap and wall-clock kill.

cited

Confidence on every finding

Each audit finding names its evidence source and why its confidence is not higher. An inferred finding cannot claim high confidence — the schema rejects it.

logged

Full audit trail

Every model call, retry, blocked request and failed attempt is recorded and rendered. The evidence panel shows the prompts and the raw responses behind each step.

fails open

No fake pass

If verification cannot get the rebuild past the checks within the retry cap, the run reports failure and writes no draft. There is no partial credit and no silent downgrade.

demo mode

No real business is touched by default

The default mode runs against a seeded fictional company. No search is performed and nobody is contacted. Live-mode prospect files are gitignored, so real business data never enters the repository.

Model routing

Nine roles, three tiers, no model ID in application code.

Code asks for a role; config/routing.json maps the role to an environment variable. Moving a role from Nano to Ultra is a config edit, not an integration. Every call goes to an NVIDIA Nemotron model on Nebius Token Factory — there is no other inference provider and no fallback to a closed model.
